remuda butler — coordination for managed agents
Run `remuda butler <verb> --help` for one command's arguments and options.

Mail:
  remuda butler send <to> "<message>" | <to> - | <to> --file PATH
  remuda butler send --from <from> <to> <message...> | --from <from> --file PATH <to>
  remuda butler send-to-leader [--done] <message...> | - | --file PATH
  Without --done, creates no new auto-close request and keeps an earlier one.
  To send text that starts with -, put -- first: remuda butler send-to-leader -- -text
  remuda butler inbox [name]
  remuda butler reply <message-id> <message...> | - | --file PATH
  remuda butler reply <message-id> --attach PATH [caption...]
  remuda butler forward <message-id> <member> [note...]

Sessions and teams:
  remuda butler close <name> [--force]
  remuda butler close --force <name>
  remuda butler sessions
  remuda butler agents [--all]
  remuda butler compact <session> [--dry-run|--force]
  remuda butler launch <claude|codex|monocle> [name] [--model M] [--writable DIR]... [--sandbox full]
  remuda butler topic new <name> [--template T] [--agent A] [--model M]
  remuda butler topic delegate <name> [--agent A] [--leader L] [--model M] [--cwd DIR] [--writable DIR]... [--sandbox full] <task...>

Approvals:
  remuda butler approve-text request SESSION - | on|off
  remuda butler approvals
  remuda butler approve <ID>
  remuda butler deny <ID>

Matrix:
  remuda butler matrix [--json] [--room ROOM] <verb> [ARGS]
  remuda butler matrix setup [OPTIONS]
  Run `remuda butler matrix --help` for its verbs: read, threads, write, rooms and setup.

Schedule:
  remuda butler schedule list
  remuda butler schedule add <name> "<M H * * *>" <text> | - [--to SESSION]
  remuda butler schedule rm <name>

Health and accounts:
  remuda butler doctor
  remuda butler quota [--report]
  remuda butler status  (0=up, 75=launching, 1=failed)

Switches and input:
  remuda butler typed-lines on|off
  remuda butler shell-lines on|off
  remuda butler status-commands on|off
  remuda butler guard on|off|status | approvals on|off|status | deny on|off|status | grants [on|off|status] | stats | verify (all switches off by default)
  remuda butler input-queue status [ID] | cancel ID | resolve ID not_sent|delivered

Notes:
Agent sessions receive REMUDA_BUTLER_AGENT_ID and REMUDA_BUTLER_LEADER_ID.
In an agent session, use `inbox`, `send <to> "..."`, and `send-to-leader ...`;
the identity comes from the daemon's registered caller session. For a long message, use
`cat <<'EOF' | remuda butler send MEMBER -` or `--file "$PWD/path"`; `reply` accepts
the same forms. Bodies are limited to 64 KiB. An outside caller uses the audited
transitional operator policy: `send` is from "operator" and `inbox` needs a name.
Unknown callers and older cores without caller fields refuse member actions;
run from a registered Butler session or upgrade core. Environment variables never
select CLI identity. Caller attribution is advisory, not an isolation boundary.
`reply` answers a message's original sender, even when it was forwarded to you;
`forward` re-delivers a message you received, keeping its sender, with a note.
`reply <message-id> --attach PATH` posts a file into that Matrix message's thread.
