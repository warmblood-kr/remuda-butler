## A1 — durable intent storage

The earlier prototype in `/private/tmp/butler-receipt-fixes` sent best-effort
after the read, losing the receipt on a crash; that logic was not copied.

- `inbox/0002` adds `read_receipt_intents`, keyed by `(recipient, message_id)`.
- `mark_read` inserts the intent before `is_read = 1` inside `BEGIN IMMEDIATE`;
  a failure rolls back both.
- Only the owner reading itself creates an intent; operator/cross-member reads
  save state only. The Rust shim has no caller identity and stays fail-closed.
- No backfill: legacy import writes read state directly; already-read rows are
  never replayed.
- Evidence: `tests/butler_read_receipt_intents.lua`,
  `tests/lua/butler_inbox_caller_identity_test.lua`,
  `tests/read_receipt_upgrade.sh`, `tests/butler_simple_inbox_acceptance.*`.

## A2 — local, idempotent delivery

- `0003_read_receipt_delivery` adds `receipt_id` (a normal Butler ULID generated
  with the intent and protected by a partial unique index), `receipt_body` (the
  exact text fixed once so a retry cannot change it), and `deferred_at` so
  Matrix rows stay pending but sort after local work. Pre-0003 rows are claimed
  once by the first drain.
- `read_receipts.lua` joins the delivered envelope, filters eligibility, and
  delivers through `mail.queue_receipt`. Matrix items stay pending for A3.
- `receipt_of` is structured in the stored envelope and loaded by
  `load_message`; body text is never the loop guard.
- Crash states are explicit: body only, body+envelope without row, row already
  accepted, and content collision. The stable ULID plus identity verification
  prevents duplicates; a collision never counts as success.
- Completion is `status='delivered'` after the local row is durable.
- Trigger: immediate drain after an agent read in `_butler_inbox`, plus a 30 s
  `butler-read-receipts` schedule for retries after restart. Bounded batch.
- Notification uses the existing safe mail-notice policy after every durable
  acceptance; its journal dedupes by `(recipient, message_id)`, so a retry
  recovers a missing notice or refuses a duplicate, and unread mail reseeds
  after restart.
- `remuda butler inbox <id>` reads only that message for the owner (read +
  intent, immediate drain); a re-view does not duplicate, another member's id
  is refused. The Rust shim and a file-only install create no intent.

## Review defects fixed

1. A1: operator reads created agent intents. Fixed with caller provenance
   (`reader_id == mailbox owner`).
2. A2 design review: `rr-...` did not fit the ULID contract. Replaced with a
   persisted ULID in the intent, generated once.
3. A2 design review: silent inbox placement was not an observable
   acknowledgment. Wired the existing notice path; the module re-attempts it on
   every durable acceptance, and the policy journal dedupes/reseeds.
4. Follow-up review: the body is now fixed in the intent, and identity checks
   use stable ULIDs/receipt_of/subject/time/body, not mutable display aliases.
5. Pre-existing A1-era parity failure: `butler_mail_parity_test` assumed the
   file inbox was authoritative. It now counts `simple_inbox` when SQLite is
   active.
6. Stabilization review: notices resolve the sender by ULID (rename follows,
   reused alias fails closed); permanent failures become `failed`, transient
   ones defer, so 50 failures cannot block a normal receipt; `mark_read` stores
   NULL for a missing receipt id; forwarded receipts name the actual reader.
7. Retry fairness: more than one page of deferred/Matrix items re-selected the
   same first 50 every tick. A durable `attempt_seq` (0004) now moves each
   tried row behind the untried ones, including equal timestamps, restarts and
   120+ rows; a failed sequence write is diagnosed, and an unbounded stream of
   non-deferred arrivals can still delay deferred work. The reader fallback is
   the canonical id, not the envelope alias.
