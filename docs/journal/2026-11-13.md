# Read receipts: durable intents, local delivery, Matrix

Date: 2026-11-13. A2: `/private/tmp/butler-read-receipts` (`1bd79a1`); A3:
`/private/tmp/butler-read-receipts-a3` (rebased on A2). Local only; no
push/merge. A1 `a020457`; A2 history through `1bd79a1`.

## A1 — durable intent storage

The prototype sent best-effort after the read and lost receipts on a crash.

- `inbox/0002` adds `read_receipt_intents`, keyed by `(recipient, message_id)`.
- `mark_read` inserts the intent before `is_read = 1` inside `BEGIN IMMEDIATE`;
  a failure rolls back both.
- Only the owner reading itself creates an intent; operator/cross-member reads
  save state only. The Rust shim has no caller identity and stays fail-closed.
- No backfill: legacy import writes read state directly.

## A2 — local, idempotent delivery

- `0003` adds `receipt_id` (ULID + partial unique index), `receipt_body` and
  `deferred_at`. Pre-0003 rows are claimed once by the first drain.
- `read_receipts.lua` joins the envelope, checks eligibility, and delivers
  through `mail.queue_receipt`.
- Crash states: body only, body+envelope, row accepted, collision; identity
  prevents duplicates.
- Completion is `delivered` after the row is durable; bounded batch.
- Notification uses the safe notice policy; its journal dedupes by
  `(recipient, message_id)`.
- `0004` adds `attempt_seq` and a single-writer sequence. Each attempt takes
  the next number (NULL first), so deferred/Matrix pages rotate across
  restarts, equal timestamps and 100+ rows.
- `remuda butler inbox <id>` reads only that message for the owner (read +
  intent, immediate drain); a re-view does not duplicate, another member's id
  is refused. The Rust shim and a file-only install create no intent.

## A3 — Matrix threaded reply

- `0005` adds the relay projection: state, txn, event id, updated time, error.
- A deferred Matrix intent drains after the local pass through the relay
  outbox. Reply id and txn come from the receipt ULID.
- Eligible only on an allowlisted-human route; durable envelope flags are the
  trimmed-route fallback, else skip.
- `io.butler.receipt_of`/`io.butler.receipt` are the structured guard; only
  agent/Butler senders may set it, so a person writing "Read receipt:" is still
  mail.
- Machine receipts skip the b2b slot and own-turn accounting. Durable
  delivered/uncertain/failed states win over missing relay evidence.
- A 5→4 downgrade drops the Matrix projection: unresolved queued/uncertain
  Matrix evidence is lost, so downgrade only when none is outstanding.

## Review defects fixed

1. A1: operator reads created agent intents. Fixed with caller provenance.
2. A2: `rr-...` was not a ULID; replaced with one persisted ULID.
3. A2: silent placement was not observable; wired the notice path, re-asked on
   every acceptance.
4. Follow-up: the body is fixed; identity checks use stable
   ULIDs/receipt_of/subject/time/body, not aliases.
5. Pre-existing parity: `butler_mail_parity_test` counts `simple_inbox`.
6. Stabilization: notices resolve by ULID; permanent failures become `failed`,
   transient ones defer; `mark_read` stores NULL; forwarded receipts name the
   reader.
7. Retry fairness: a deferred page re-selected the same rows; `attempt_seq`
   rotates them across restarts and 120+ rows. A failed write is diagnosed;
   unbounded non-deferred inflow can still delay deferred work.
8. The credential-store scan flagged `mark_read` as an OS-store read; the false
   positive is excluded and asserted.
9. A3: the mail writer dropped the relay flags and the reload used Lua's
   unsupported `(true|false)`. Both are fixed; save/reload after route trim is
   tested.
10. A3: a missing result could resend. Durable `delivered` wins; `queued` with
    lost evidence becomes `uncertain`; a throw (even after acceptance) is
    uncertain; status/projection failures never send; identity reuse is
    refused.
11. A2: `inbox <id>` did not read. It now marks read + intent atomically;
    re-view, cross-member, SQLite-failure and Matrix tests added.
