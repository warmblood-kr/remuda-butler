## Decisions applied from review

- `accepted_queue` is accepted only as the exact `{outcome}` object. Empty,
  arbitrary or non-string `reason`, and unknown keys, are UNCERTAIN.
- `definitely_not_written` is strict: `server_identity`, `server_unverified`
  and `unsupported_platform` join the dead set (sticky disabled, alert, zero
  PTY). `invalid_args`/`invalid_request` are proven pre-write refusals on a
  live binding: retire the reservation and use the bounded retry schedule with
  an exhaustion alert. Missing/unknown/wrong-typed reasons are UNCERTAIN.
- Canonical text is constructed from the dense ID list and compared exactly
  (single: original ID; multi: count only); duplicate/map/hole IDs are refused
  and the encoded request is bounded to 64 KiB before any spawn.
- The attempt snapshot freezes the native path/nonce/row/instance before any
  yield. The post-journal fence revalidates the live binding, so a mid-write
  toggle or replacement dispatches nothing and never falls back to PTY.
- A listing failure proves nothing and retries; a confirmed missing or stale
  target disables the binding.
- Launch: one kind-gated plan per launch; `mkdir_new` `exists` is reused on
  relaunch with a fresh nonce leaf; env carries only the nonce; join requires
  the exact live row id and instance or the session is sticky `disabled`;
  roster stores only path+nonce and adoption requires the exact instance.

## Sticky scope (lead decision A, 2026-11-05)

Sticky means the protocol/target lifetime, not the Lua image: a bound native
session never becomes PTY, and `disabled` is an in-memory diagnostic state that
lives only for that image. The roster stays `path`+`nonce` only. A same-instance
reload adopts the same fixed binding and may perform one fresh authoritative
helper validation against that same path+nonce+row.id+instance; it never invents
a new target, and a still-dead helper re-disables with one alert. Journal
DISPATCHING/UNCERTAIN/accepted-unread IDs remain suppressed, so reload never
replays them. `tests/butler_native_adoption.lua` covers that regression: adopt
the same binding, suppress three states, deliver one fresh ID through the same
target with zero PTY.

Launch seam: the owned nonce directory is NOT the `--binding` argument. The
wrapper takes the manifest FILE path and creates it inside the parent, so the
plan passes `<nonce-dir>/manifest.json`; the unit regression asserts the
directory is created, the file is not, and the builder forwards the exact file
path. (QA newlaunch blocker, 2026-11-05.)

User-visible boundary: a typed dead helper/manifest refusal becomes `disabled`
plus a sender alert; an untyped runner or spawn failure stays `uncertain` with
no retry and no PTY. The latter is deliberate (the helper may have run), so it
does not borrow the disabled diagnostic state.
