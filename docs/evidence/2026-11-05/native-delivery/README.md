# Native-session probe evidence

These are sanitized installed-client results; A/B/C precede implementation, while the actual-wrapper review covers the new core candidate. All endpoint credentials and private temporary roots were removed after owned processes stopped. Recorded IDs/PIDs/ports are expired test identities.

- OpenCode2.2.5 probes A/B/C were executed by native-delivery-qa after the lead approved each phase. A uses the actual protected foreground server without model execution. B/C use the actual server and original TUI with a local synthetic Chat-SSE model provider, no tools or real provider credentials. A proves admission/restart pending state; B proves consumption, original busy-turn order, draft separation and immutable-ID reconciliation; C proves fixed-target A delivery while the original TUI displays B. The refusal check in C is harness-only until the product adapter exists.
- `bridge_probe.lua` is the sanitized Lua RPC seam used by probe H; it loads the product modules unchanged and only bridges fs/process/hash to the QA driver. The QA controller is owned by native-delivery-qa and is not vendored under the repository language-boundary rule; the result JSON is the measured record.
- `probe-h-result.json` records the independent phase-2 bridge matrix: the actual Lua `native_launch.prepare` -> OpenCode builder argv -> real wrapper creates the absent manifest FILE, then actual notice/journal/dispatch modules with DI atomic storage/SHA-256 and the real helper subprocess against the same original TUI and local mock. Idle/busy/draft/fixed-A pass; wrong nonce, removed manifest and stale wrapper disable with an alert; a discarded helper ACK becomes durable UNCERTAIN and does not replay in a fresh image; zero bridge PTY throughout. Scope excludes full `remuda.new`/chooser/main boot and a genuine HTTP lost-response fault; `attached=true` is an injected row over an owned PTY.
- [Actual-wrapper review](actual-wrapper-review.md) records independent original-TUI idle/busy/draft and fixed-A/UI-B delivery plus refusal/cleanup tests of the new core launcher/helper. Caller-discarded ACK is not a forced HTTP lost-response test. Keyboard quit remains unproved; owned TUI termination cleanup passed.
- Codex0.166.0 probe was executed by opencode-delivery-design with an original private app-server/TUI and read-only/on-request policy. `codex-dedupe-admission.jsonl` records three different queue receipts for one client message ID. Independent history inspection found three completed turns. This disproves an idempotent-admission assumption; it is not a stress or crash-recovery result.
- `codex-fixed-thread-launch.md` records the separate failed empty-thread launch prerequisite. No model-seed workaround or successful attachment is claimed.

No production/default daemon, session input, configuration or credential store was modified. Same-server/TUI assertions apply before orderly restart; a restarted server is explicitly a new engine. These observations do not prove arbitrary provider/tool/permission-pause behavior, PID reuse resistance, or exactly-once processing. See [support assessment](../../../concepts/native-session-support.md) and [implementation plan](../../../concepts/native-notice-plan.md); core unit checks and Butler durable-journal/integration checks remain distinct from client behavior probes.
