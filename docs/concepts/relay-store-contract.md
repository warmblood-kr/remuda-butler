## Store shape and API
relay_store.open(opts)->store (mod-owned relay DB; marker gate before legacy decode/open side effects). import_prepare(manifest), import_source(id,raw), verify_import(),activate()->writer. import_source stages immutable raw; import_batch(id,limit<=64) resumes bounded pages. writer={store_id,owner_id,epoch}. All mutations require writer+operation_id, full transactional CAS and rows==1; epoch advances only after verified prior-owner stop and external fence, never TTL.

accept_batch(writer,{operation_id,expected_cursor,next_cursor,events}) atomically stores event dedup/pending delivery ledger and cursor. Cursor equality only; strings opaque. cursor(),dispatch_page(limit),complete_dispatch(writer,event_id,inbox_receipt,changes),get/put/delete/page for records; resolve_operation(id) after ambiguous commit. Reads paginated; no full-state boot reconstruction. reply_dispatch_page handles outbound.

Schema sketch relay_store_schema.sql: authority singleton, cursors, keyed records, event ledger, operations, reply intents, import progress. Known room-nested collections split parent_key/record_key; arrays retain ordinal including duplicates. Perrecord complete JSON retains unknown nested fields. Unknown root fields use extension namespace and retain type/value; unknown future format version blocks. No authority whole-state JSON blob. Immutable raw staging allowed only during migration, retired after verified activation. Single oversized record must be split losslessly or block with precise class; never drop/truncate. Maxsource32MiB, maxrecord256KiB/8192nodes, page64 rows provisional; importer rejects beyond those explicit limits and documents recovery rather than claiming arbitrary-size support.

## CrossDB delivery and unknown outcomes
Relay commits pending event+cursor before inbox call. Inbox must accept_external(stable source_key,immutable delivery payload) atomically dedup+mail insert; same key/same payload -> same mailID, changed payload -> conflict. Key includes stable Matrix account/room/event/destination identity, independent of storeID/epoch/process. Relay completes only after receipt. Crash after inbox commit repeats same accept, never creates fresh key. Delivery context frozen before first attempt; later payload rewrite requires conflict handling. No crossDB atomicity/exactly-once external effect claim.

Reply attempts/preHTTP claims durable; imported nonterminal without proven attempts0 defaults uncertain. In-flight/unknown write never replays. HTTP success receipt+sent claim DB first; save-only recovery if commit unknown, no resend. Every callback validates owner identity/epoch immediately before durable transition and POST; legacy code unable to check fence cannot be retroactively fenced.

## Authority and failure contract
Durable importing marker BEFORE first migration write; import-only, no network/delivery. Anchors prevent missing-marker fallback. Activation requires zero missing/skipped/conflict classes and perpath values/types/array-order equality, immutable source, schema/account identity, proven owner quiescence, marker fsync file+parent and DB WAL/FULL durability. DB commit then active marker publish; interrupted publish remains import-only. After promotion ANY DB/marker mismatch/missing/corrupt/full/busy/too-new error blocks, never legacy read/write fallback. Unknown commit disposes handle and blocks new work until reopening/querying operation_id establishes outcome. No numeric cursor compare, implicit rollback/export or JSON repair.
