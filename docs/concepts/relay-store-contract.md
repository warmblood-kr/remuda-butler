# Full relay SQLite authority contract (design only)

Scope replaces ALL legacy relay JSON authority, not only receipts. Prior cutover/epoch HOLD designs remain safety floor; tests/contracts are specs, not product. Live activation BLOCKED: legacy orphan owner unknown. Local95kB/2263 values; remote unknown. Old uncertain2 no replay.

## Store shape and API
relay_store.open(opts)->store (mod-owned relay DB; marker gate before legacy decode/open side effects). import_prepare(manifest), import_source(id,raw), verify_import(options),activate()->writer. verify_import is bounded (max_rows<=64,max_bytes<=262144,max_nodes<=8192; defaults are ceilings): false/backlog with a durable checkpoint until true/ready/certificate_id; callers loop. Activation checks indexed certificate/checkpoint/authority revision/owner/epoch equality and refuses backlog. Unknown verify COMMIT returns unknown_commit; reconcile by reopen. import_source stages immutable raw; import_batch(id,limit<=64) resumes bounded pages. writer={store_id,owner_id,epoch}. All mutations require writer+operation_id, full transactional CAS and rows==1; epoch advances only after verified prior-owner stop and external fence, never TTL.

accept_batch(writer,{operation_id,expected_cursor,next_cursor,events}) atomically stores event dedup/pending ledger and cursor (equality only; opaque). cursor(),dispatch_page(limit),complete_dispatch(writer,event_id,inbox_receipt,changes),get/put/delete/page for records; resolve_operation(id) after ambiguous commit. Reads paginated; no full-state boot. reply_dispatch_page handles outbound.

Schema: authority singleton, cursors, keyed records, event ledger, operations, reply intents, import/verify progress. Room-nested collections split parent_key/record_key; arrays retain ordinal including duplicates. Per-record JSON retains unknown nested fields; unknown roots use an extension namespace. No authority whole-state JSON blob. Raw staging is migration-only and retired after verified activation. An oversized record blocks with a precise class; never drop/truncate. Max source 32MiB, record 256KiB/8192 nodes, page 64 rows provisional.

## CrossDB delivery and unknown outcomes
Relay commits pending event+cursor before inbox call. Inbox must accept_external(stable source_key,immutable delivery payload) atomically dedup+mail insert; same key/same payload -> same mailID, changed payload -> conflict. Key includes stable Matrix account/room/event/destination identity, independent of storeID/epoch/process. Relay completes only after receipt. Crash after inbox commit repeats same accept, never creates fresh key. Delivery context frozen before first attempt; later payload rewrite requires conflict handling. No crossDB atomicity/exactly-once external effect claim.

Reply attempts/preHTTP claims durable; imported nonterminal without proven attempts0 defaults uncertain. In-flight/unknown write never replays. HTTP success receipt+sent claim DB first; save-only recovery if commit unknown, no resend. Every callback validates owner identity/epoch immediately before durable transition and POST; legacy code unable to check fence cannot be retroactively fenced.

## Authority and failure contract
Durable importing marker BEFORE first migration write; import-only, no network/delivery. Anchors prevent missing-marker fallback. Activation requires zero missing/skipped/conflict classes and per-path values/types/array-order equality, immutable source, schema/account identity, proven owner quiescence, marker fsync file+parent and DB WAL/FULL durability. DB commit then active marker publish; interrupted publish remains import-only. After promotion ANY DB/marker mismatch/missing/corrupt/full/busy/too-new error blocks, never legacy read/write fallback. Unknown commit disposes the handle and blocks until reopen/query proves the outcome. No numeric cursor compare, implicit rollback/export or JSON repair.
