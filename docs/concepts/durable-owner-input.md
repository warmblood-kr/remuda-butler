# Durable owner plaintext queue

Owner-approved prepared text and authenticated live owner `!` plaintext enter a bounded logical FIFO. Guard PermissionRequest stdout/RPC replies, ordinary mail/notices, startup keys and `!!` shell commands remain separate. Acceptance means private durable intent retained; delivery means provider outcome, never model consumption.

Prepared approval binds request ID/nonce/exact bytes and original Butler principal/start marker/core instance before enqueue. Owner lines bind room/event/sender/body and original exact target; replay never resolves a changed alias. Current owner allowlist and feature switches are checked again before dispatch. Authenticated event parsing and instance ownership remain existing Butler gates.

The queue uses real core advisory lock and private atomic replacement (Unix file+parent fsync). No in-memory durability fallback. Receipt follows persistence; retry of the same stable ID reaffirms persistence without new sequence. Changed immutable fields refuse. A private initialization witness precedes the first empty ledger: failed initialization or later ledger loss refuses storage_missing rather than resetting. Missing/corrupt witness and unreadable/corrupt ledger also refuse. Recovery requires an operator to inspect/restore the complete private namespace; never delete the witness to resume automatically. External deletion of both files is outside this filesystem guarantee. No power-loss hardware simulation claimed.

Bounds: 256 retained requests/tombstones,32 pending per exact session stream,8192 payload bytes per item,2MiB total payload and3MiB ledger. Capacity exhaustion refuses acceptance; no automatic deletion, expiry or eviction. Tombstones retain bytes/digests privately for stable-ID verification. Public status receipts exclude payload, prompt, nonce and owner/event proof. Explicit future retention policy needs separate review.

Per-stream head blocks later inputs, including uncertain/quarantined heads. Different streams can progress; worker limits four heads/tick. Approved items survive approval TTL via queue-authoritative reconciliation before sweeps. Pre-intent blockers defer with bounded backoff, without finite retry expiry. Workflow/draft/modal/human guards remain; unknown renderer alone allows admission under owner policy.

Before physical dispatch: audit and admission checks, durable dispatch_intent, existing prepared delivery marker, then repeat identity/admission checks. Any post-intent ambiguous/false/throw/late/unverified result becomes uncertain and never replays automatically. Restart converts unresolved dispatch_intent to uncertain. A changed exact instance quarantines the original stream; never retarget queued bytes. Owner `!` keeps its existing separate RET; failure after text is uncertain and never retypes text or repeats RET. Its own nonempty composer is accepted only with exact current parser text and a post-write internal ownership callback: trusted numeric human_idle sampled before text (>=10s or explicit infinity), nonreversing monotonic clock within10s, unchanged attachment/actual instance and continuous idle. Missing/reset evidence or different draft stays uncertain. Auth/workflow/modal checks run independently at each guarded key boundary; key must return exactly true. These sampled checks do not atomically exclude human input after the final sample; a future native input-generation token would be stronger.

Required physical capability: native provider must pin the actual session object and validate expected instance, then perform the whole semantic type_text or key on that same object. Lua name-based preflight alone is insufficient. Adapter requires `_input_instance_bound_version==1` and both `_input_type_text_if_instance`/`_input_key_if_instance` functions; native companion f82bfe0 implements this additive contract. Installed core remains unmodified and lacks it. Absent capability defers provider_identity_unavailable, preserving accepted intents with zero physical writes. No launcher/default/backend changes or NativeStore durable outcome claim.

Operator-only `input-queue status [ID]`, `cancel ID`, `resolve ID not_sent|delivered` expose redacted receipts. Cancel only unattempted queued/quarantined requests. Explicit resolution records owner knowledge and releases the head without replay. Uncertain inputs cannot be casually cancelled as unattempted. Audit must persist before resolution.

Tests separate actual private core storage/lock/restart from synthetic terminal provider behavior and the real Matrix relay adapter boundary. None touches live panes, attaches a model, or proves application consumption. Existing ordinary notice busy policy remains unchanged.
