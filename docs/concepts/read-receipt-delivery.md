# Local read-receipt delivery

Owner-facing outcome: when a member fetches a message from its Butler inbox,
the original sender receives one automatic acknowledgment in its own mailbox.

This is the local, SQLite slice (A2). Matrix delivery is not implemented: a
Matrix-origin intent stays `pending` for the relay slice (A3).

## Identity and durability

- A1 already records one `pending` row per real unread→read transition, in the
  read transaction.
- Migration `inbox/0003_read_receipt_delivery` adds `receipt_id`. It is a normal
  Butler ULID generated by the reader and committed with the intent, so the
  receipt is an ordinary mail message, not a custom ID format.
  `read_receipt_intents_receipt` is a partial unique index on it.
- A pre-0003 intent has no `receipt_id`; the first drain claims one with a
  conditional `UPDATE ... WHERE receipt_id IS NULL OR receipt_id = ''`, then
  reads back the stored value. Single-writer in this daemon, but a losing writer
  reads the winner's ULID instead of overwriting it.
- `intent.read_at` fixes the receipt's `created_at`, so a retry produces the
  same body and envelope values.

## Eligibility

The scan joins `simple_inbox` on `(recipient, message_id)`; the intent does not
copy the sender. `read_receipt_intents.recipient` is the hex mailbox component
and decodes to the reader's canonical id.

- **eligible:** local envelope with a non-empty `from.id`, sender != reader,
  no structured `receipt_of`.
- **skipped (durable):** `receipt_of` present, reserved `schedule` or system
  sender, self-mail, no sender ULID, non-local non-Matrix sender.
- **deferred (stays pending):** Matrix sender or Matrix route metadata. No
  Matrix I/O and no acknowledgment in this slice. `deferred_at` is set so these
  rows sort after local work and cannot starve it; they remain `pending` for A3.
- An unreadable/missing original envelope stays pending; it is never reported
  as a delivery.

The recursion guard is the structured `receipt_of` field written into the
stored envelope, parsed by `load_message`, and preserved across restart. Content
text is never the guard.

## Crash-safe delivery

`mail.queue` grew a stable path (`queue_receipt`). An existing message at the
fixed ULID is reused only when `receipt_of`, `from.id` and `to.id` match this
receipt; an unrelated message at that id is a collision and leaves the intent
pending. The accepted states:

1. body file only: identical content is reused; different content is a
   collision. The envelope is then written.
2. body + envelope, no inbox row: the verified envelope is reused and the row
   is inserted.
3. inbox row already present: `already=true`; no rewrite and no new notice.
4. content conflict: error, intent pending, no false success.

Only after the inbox row is durable does the drain set `status='delivered'`. A
crash between acceptance and that mark is a verified retry, not a duplicate.

SQLite is authoritative for intents and `simple_inbox`; the message/object files
are the body store. A file-only install has no intents and the drain is an
explicit no-op. One daemon process owns both stores while draining.

## Notification

The receipt is delivered through the existing mail queue. For a newly accepted
receipt only, the module asks main.lua's `notify_mail_delivery` to type the
existing mail notice, with the detail "read receipt for <original id>". The
safe notice policy (journal, busy-pane, retry) owns whether and when it types.
An already-accepted retry does not notify again, so a crash after acceptance
cannot produce a duplicate notice.

## Evidence

- `tests/butler_read_receipt_delivery.lua` (fast, isolated): A→B one correlated
  receipt and one notice; batch distinct receipts; duplicate read/restart;
  crash after acceptance before the status mark (retry marks, no duplicate mail
  or notice); body-only partial crash; id collision; content conflict;
  receipt/self/schedule/unaddressable exclusions; Matrix left pending; file-only
  fallback no-op.
- `tests/read_receipt_upgrade.sh`: real SQLite upgrade to v3, real drain,
  delivered status, ULID identity matching the delivered mail row, `receipt_of`
  correlation, sender read of the receipt skipped with no new mail, second
  restart stable.
- `tests/butler_simple_inbox_acceptance.sh`: real SQLite inbox across process
  restarts with the new schema.

## Not in this slice

Matrix reply/outbox delivery, uncertain-send retry policy, receipt status
display, and any re-acknowledgment of already-skipped intents.
