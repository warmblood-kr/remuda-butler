# Local read-receipt delivery

Outcome: a member fetches a message, and the original sender gets one automatic
acknowledgment in its own mailbox.

This is the local, SQLite slice (A2). Matrix delivery is not implemented: a
Matrix-origin intent stays `pending` for the relay slice (A3).

## Identity and durability

- A1 records one `pending` row per real unread→read transition, in the read
  transaction.
- Migration `inbox/0003_read_receipt_delivery` adds `receipt_id` and
  `receipt_body`. The id is a normal Butler ULID generated by the reader and
  committed with the intent, so the receipt is an ordinary mail message.
  `read_receipt_intents_receipt` is a partial unique index on it. The body is
  claimed once, so a retry cannot compute a different text.
- A direct caller without an id stores **NULL**, not `''`, so unidentified
  intents do not collide. A pre-0003 row is claimed once by the first drain.
- `intent.read_at` fixes `created_at`, so a retry produces the same body and
  envelope values.
- The receipt names the reader from the canonical id via the identity store,
  not the envelope's `to` alias, so a forwarded copy names the actual reader.

## Eligibility

The scan joins `simple_inbox` on `(recipient, message_id)`; the intent does not
copy the sender. `recipient` is the hex mailbox component and decodes to the
reader's canonical id.

- **eligible:** local envelope with a non-empty `from.id`, sender != reader,
  no structured `receipt_of`.
- **skipped:** `receipt_of` present, reserved `schedule`/system sender,
  self-mail, no sender ULID, non-local non-Matrix sender.
- **deferred:** Matrix sender or route metadata. `deferred_at` sorts it after
  local work; it stays `pending` for A3. No Matrix I/O here.
- An unreadable/missing envelope stays pending, never reported as delivered.

The recursion guard is the structured `receipt_of` in the stored envelope,
parsed by `load_message` and preserved across restart. Content text is never the
guard.

## Crash-safe delivery

`mail.queue` grew `queue_receipt`. An existing message at the fixed ULID is
reused only when `receipt_of`, sender/recipient ULIDs, subject, time and body
match; display aliases are not identity. An unrelated message is a collision.

1. body only: identical content is reused; different content is a collision,
   then the envelope is written.
2. body + envelope without a row: verified envelope reused, row inserted.
3. row present: `already=true`; no rewrite, no new notice.
4. content conflict: error, terminally failed, no false success.

Only after the row is durable does the drain set `status='delivered'`. A crash
between acceptance and that mark is a verified retry, not a duplicate.

## Failure fairness

A permanent collision/conflict becomes `failed` and leaves the pending page. A
retryable error stays `pending` with durable `deferred_at`, so it sorts behind
newer work. Permanent failures do not consume the delivery batch, so 50 failed
intents cannot block a normal receipt.

SQLite owns intents and `simple_inbox`; files store bodies. A file-only install
has no intents and the drain is a no-op.

## Notification

The receipt uses the existing mail queue. After every durable acceptance,
including an accepted-but-unmarked retry, the module asks main.lua's
`notify_mail_delivery` to type the existing notice with the detail "read receipt
for <original id>". The sender is resolved by durable ULID, not the stored
display alias: a rename follows the id, while a reused alias fails closed and
cannot clear another member's `--done` mark. The notice policy's journal
reserves `(recipient, message_id)`, so a retry recovers a notice that never
started or refuses a duplicate. Unread mail is reseeded after restart; a receipt
the sender already read is skipped.

## Evidence

- `tests/butler_read_receipt_delivery.lua` (fast, isolated): A→B one correlated
  receipt/notice; batch; duplicate/restart; crash before the status mark (retry
  marks and re-asks the notifier); crash before the notice (retry notifies);
  fixed body across an alias change; body-only partial crash; collision/conflict
  terminally failed; 50 failures then a normal receipt in the same drain;
  forwarded-mail reader identity; exclusions; Matrix pending; file-only no-op.
- `tests/lua/butler_inbox_caller_identity_test.lua`: real notice path with a
  renamed then reused alias (correct target, no wrong `--done`), and a real
  forwarded mail whose receipt names the actual reader.
- `tests/read_receipt_upgrade.sh`: real SQLite v3 upgrade/downgrade, real drain,
  ULID/body correlation, unidentified intents storing NULL, loop skip, second
  restart stable.
- `tests/butler_simple_inbox_acceptance.sh`: real SQLite inbox across restarts.

## Not in this slice

Matrix reply/outbox delivery, uncertain-send retry policy, receipt status
display, and re-acknowledgment of already-skipped intents.
