## Bounded implementation flow

1. Startup opens store gate and loads only marker/identity/cursor + bounded counts. No state table materialization, whole-state pairs()/sort/encode/decode, or lazy proxy that secretly fetches everything. Generic page(namespace,{parent_key,after_key,limit<=64}) stable order; arrays preserve ordinal. get reads ONE bounded record. put/delete change only addressed row; untouched JSON retains all unknown members/tokens. Editing numbers outside Lua exact range requires token-preserving update or rejection.
2. Sync response ingestion builds bounded event/record deltas. accept_batch checks expected opaque cursor equality, dedup inserts event ledger/pending rows, applies related policy deltas, and advances cursor in ONE SQL commit. Batch operation_id and immutable typed input witness make retries stable; different input same ID conflicts. Split response into chunks only with durable batch progress and cursor finalization, never advance past unrecorded events. No callbacks inside transaction.
3. Pending worker dispatch_page<=64; event-specific context enrichment is separately persisted and frozen before first inbox acceptance. Delivery key = stable account/room/event/destination. Inbox accept_external commits idempotent mail receipt in its own DB. Relay complete_dispatch atomically records receipt, route/subscription changes and processed disposition. Crash gap repeats SAME key/payload. No new ack sidecar. Legacy ack+drain snapshots imported idempotently as legacy-delivered evidence; source sidecars retained until separate authorized archival, never deleted by store.
4. Outbound queue stores intent first; CAS claim verifies current rootcap+epoch immediately before POST. Successful HTTP commits receipt+sent claim first; unknown HTTP/commit outcomes remain uncertain/save-only. No imported unproven prepared/inflight row can send. Never replay old uncertain2. Poll/HTTP cancellation cannot revoke an issued request. owner check at callback transition prevents stale DB writes; oldowners stop before new cap.
5. Approvals/invite/typed-line immediate side effects cannot run while merely planning cursor batch. Persist individual intent/dedup first, execute afterward under currentcap, persist result separately. Preserve each API's existing uncertainty rules. Timers are liveness only; no callback invocation/timer replay to heal existing runtime. In-memory context/request queues must drain or convert durably before cutover; unknown legacy generation blocks.
